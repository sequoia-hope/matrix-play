3. Phase P1: In2.Cu QSPI XIP Bus & USB 2.0 Differential Pair (3D FDTD + SPICE) PASS w/ SLEWFAST=0

On JLC04161H-7628, In2.Cu is separated from the In1.Cu solid ground plane by the 1.065 mm FR-4 core rather than a thin prepreg. Full-wave 3D openEMS FDTD extraction reveals two important physical consequences on p2-132:

  • Single-Ended QSPI Bus (0.10 mm width, 0.40 mm pitch, 15.8 mm length): Characteristic impedance rises to 109.21 Ω with inductive coupling kL = 0.364 (NEXT = -10.46 dB). Driving RP2350 PADS_QSPI at SLEWFAST=1 (0.85 ns) causes 3.77 V overshoot at U4 and 313 mV crosstalk, whereas keeping SLEWFAST=0 cuts crosstalk 5.1× to 61.4 mV (3.33 V peak, zero ringing).
  • Edge-Coupled USB 2.0 Pair (w = 0.15 mm, inner gap s = 0.1875 mm on In2.Cu): Tight broadside-free edge coupling across the 0.1875 mm gap brings odd-mode impedance down to 46.23 Ω → Zdiff = 92.47 Ω (S11 = -51.3 dB @ 60 MHz), matching the 90 Ω USB 2.0 spec within 2.8%!

4. Phase P2: VREG_LX 3.3 μH Buck Loop & In1.Cu “LX cutout L2” Trade-Off LAYOUT + ADC FINDING

Real Layout Discovery on parallelogram.kicad_pcb: Because B.Cu (VREG_LX pour + L1) already sits 1.30 mm away from In1.Cu across the 1.065 mm core, the rule-area keepout LX cutout L2 (x=[1.65..3.30], y=[9.15..14.70] on In1.Cu) reduces LX-to-GND parasitic capacitance by only 47.9 fF (284.5 → 236.6 fF), while opening a +52.0 dB near-field aperture onto front-side LED traces (CS2_10..12: -123.2 → -71.2 dB @ 200 MHz) and slightly raising hot-loop inductance (4.199 → 4.435 nH). Even more importantly, VBAT_SENSE on In2.Cu crosses 0.21 mm directly above the B.Cu VREG_LX pour (Ccoup = 254.0 fF), injecting 147.7 mV switching spikes onto the un-decoupled 50 kΩ divider! Our firmware eliminates this via 8× ADC0 oversampling; on a rev-B spin, keep In1.Cu solid and route VBAT_SENSE west of x = 1.0 mm. Crystal Y1 (11.8 mm south) sees only 24.2 μV (M = 0.322 pH, completely immune).

  • 1 MHz Fast-Mode Plus Timing: Total extracted capacitance of the 46.64 mm I2C_SDA bus is 23.3 pF. With R1/R2 = 1 kΩ, rise time is 19.74 ns (well under the 120 ns Fm+ limit; 4.7 kΩ would degrade to 92.84 ns).

7. Notes from Running Real Dual-Core Firmware on picoem (rp2350-emu v0.2.6) EMULATOR OBSERVATIONS

  • Dual-Core + PIO0 + DMA + VFPv5 Fidelity & Speed: picoem’s Serial oracle-validated core executed 9,905,352 master cycles (Core 0 = 9,905,349, Core 1 = 9,905,352) including VFPv5 floating-point shaders, inter-core SIO_FIFO + SEV/WFE handshakes, DMA Ch0 DREQ_PIO0_TX0 pacing, and PIO0 SM0 OUT PINDIRS + IN PINS + AUTOPUSH at an effective 19.6 MHz in just 505 ms of host time!
  • Silicon Bootrom CP7 Canary Finding (Both Cores): Probing unmodified bootrom-combined.bin confirmed Core 0 hits the known CP7 rcp_iequal canary check in ___step4_init_rcp_seeds, and revealed that Core 1’s silicon bootrom wait_for_vector loop at 0x0000_01C6 also executes CP7 canary instructions (fe19 c735) immediately upon waking from WFE on the first FIFO word. Supplying our 356-byte pure-Thumb architectural RP2350 ROM shim (p2-132-rom-shim) let both cores boot cleanly from reset vector 0x0000_0000 with full PICOBIN validation and 6-word SIO FIFO launch!
  • TICKS Peripheral Clock Source Observation: In crates/rp2350-emu/src/peripherals/ticks.rs, each enabled tick domain currently increments once per sys_clk cycle (150 MHz) rather than once per clk_ref cycle (12 MHz XOSC), causing TIMER0 to advance 12.5× faster than real silicon when SDK/firmware programs TICKS.TIMER0.CYCLES = 12. Using hardware PIO0 AUTOPUSH for I²C readback made our firmware 100% immune to timer rate differences across silicon and emulator.
  • PIO MOV ISR, NULL, Armv8-M LDA/STL, VSEL/VMAXNM, & WFE Cycle-Debt Findings: Co-simulation uncovered four subtle instruction/peripheral edge cases in rp2350-emu v0.2.6: (1) PIO MOV ISR, NULL (sm.rs:929) clears isr without resetting isr_count (solved via PUSH NOBLOCK + RXF0 drain); (2) Thumb-2 LDA/STL (execute_thumb32.rs:875) falls through to LDRD/STRD with Rt2 = PC (solved via read_volatile/write_volatile + dmb sy); (3) Armv8-M FPU fpu_v8m_dp (execute_fpu.rs:630,639) decodes VSEL/VMAXNM/VMINNM destination bit D from hw0[4] instead of hw0[6] and cc from hw0[6:5] instead of hw0[5:4], misrouting VSELGT writes on even S2k registers to S(2k+1) (solved via IEEE-754 integer-order f32_clamp + VCVT.S32.F32); and (4) step_pair_arm freezes a sleeping core’s cycle counter during WFE and bursts accumulated cycles inside a single emu.step() upon wake (solved via YIELD polling so host open-drain GPIO co-sim observes every I²C clock edge with 0 NACKs).
  • Open-Drain Bus Modelling via gpio_external_mask: Because update_gpio() drives 0 when both pio_oe and sio_oe are released (0), open-drain protocols (I²C, 1-Wire) work cleanly when the board harness sets gpio_external_mask and computes wired-AND pull-ups against (pio.pad_oe, pio.pad_out, sio.gpio_oe, sio.gpio_out) each quantum.
